# Ручне тестування прототипу — Частина 2

Цей документ призначений для фактичного проходження прототипу в браузері. Не позначати тест як успішний, доки дію не виконано й результат не спостережено.

## Підготовка
1. Завантажити HTML-файл [v1](../build/v1/index.html) або відкрити його через GitHub Raw.
2. Запустити файл у сучасному браузері.
3. Переконатися, що видно підказку, три символи, індикатори прогресу та кнопку перезапуску.
4. Для незалежної проби попросити людину поза командою виконати завдання без пояснення правильної послідовності.

## Тест-кейси

| ID | Початковий стан | Дія | Очікуваний результат | Фактичний результат |
|---|---|---|---|---|
| TC-01 | Початковий екран v1 | Натиснути листок, краплю, зірку | Прогрес доходить до 3/3, з'являється повідомлення про відкриття проходу, кнопки символів блокуються | Заповнити після запуску |
| TC-02 | Початковий екран v1 | Натиснути неправильний перший символ | Прогрес залишається 0/3, з'являється повідомлення про помилку | Заповнити після запуску |
| TC-03 | Один правильний крок | Натиснути неправильний символ | Прогрес скидається до 0/3, індикатори очищуються | Заповнити після запуску |
| TC-04 | Головоломку завершено | Натиснути кнопку перезапуску | Початкове повідомлення відновлюється, індикатори порожні, кнопки активні | Заповнити після запуску |
| TC-05 | Початковий екран v1 | Переміщатися клавішею Tab і натискати Enter/Space на кнопках | Елементи доступні з клавіатури, фокус помітний, дії виконуються | Заповнити після запуску |
| TC-06 | Вікно вузьке (наприклад, мобільна ширина) | Переглянути розташування елементів | Кнопки не перекриваються, текст читається, сторінка не потребує горизонтального прокручування | Заповнити після запуску |

## Незалежна проба
Тестувальнику можна сказати лише: «Спробуй активувати механізм і відкрити прохід». Не підказувати послідовність і не пояснювати інтерфейс.

Зафіксувати:
- дату, браузер і тип пристрою;
- чи зрозумів учасник мету без допомоги;
- першу дію та послідовність наступних дій;
- місця зупинки, помилки або звернення по допомогу;
- короткий коментар учасника, якщо він погодився;
- які зміни варто зробити на основі спостережень.

Не публікувати ім'я, контакти, фото чи інші персональні дані учасника без його згоди. Для звіту достатньо коду на кшталт «Учасник 1».

## Докази
Додати скриншоти початкового стану, помилки, успішного завершення та перезапуску. Для незалежної проби додати лише ті докази, на які учасник погодився. Після внесення змін повторити відповідний тест-кейс на v1 та записати результат у [журнал тестування](part-2-test-log.md).
